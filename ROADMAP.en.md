# Roadmap

This document tracks the medium-term and long-term direction of `boss-agent-cli`. Issues and PRs are welcome for any of the areas below.

## Released

- ✅ v3.4.118 (2026-11-19): the wizard `crawl_stop` goal rejects finished runs; `stats` / `digest` reject whitespace-only `-o` paths (Issues #1786 #1788).
- ✅ v3.4.117 (2026-11-19): `ai config --base-url` rejects unparseable hosts and ports; redaction covers passwords embedded in URLs; error objects returned by AI services with HTTP 200 surface their message and recovery advice; `hr greet` recognises quota pages whose flags drift in type; recruiter commands reject blank IDs; `hr jobs` follow-up commands quote job IDs (Issues #1778–#1783).
- ✅ v3.4.116 (2026-11-19): resuming a crawl run persists its status first, so stop requests during the resume window are accepted; wizard `crawl_start` rejects a `query` / `city` that differs from the checkpoint; corrupt result rows point follow-up commands at the real run id; `openai-tools` / `anthropic-tools` exports no longer carry top-level combinator or conditional keywords; `boss_wizard` declares the fields required to run (Issues #1771–#1775).
- ✅ v3.4.115 (2026-11-19): free-text redaction covers composite credential keys such as `access_token=` / `x-api-key=`; the `--exit-codes` prescan stops at `--`; open-file hints prefix leading-dash paths with `./`; resume names with Windows-illegal characters use portable filenames while legacy files stay reachable (Issues #1765–#1768).
- ✅ v3.4.114 (2026-11-19): default chat export paths are validated before authentication and snapshots; shared atomic writers check targets before and after staging, so FIFOs and other special files are never replaced silently (Issues #1760, #1762).
- ✅ v3.4.113 (2026-11-18): local write boundaries tightened — `agent resume`, the request lease, crawl artifacts and default resume/chat export paths now refuse symlinks, FIFOs and special files instead of silently replacing user files or writing outside the data directory (Issues #1751, #1753, #1755, #1757).
- ✅ v3.4.112 (2026-11-18): automation writes now refuse symlinks — queue appends no longer write through link targets, state and queue rewrites no longer silently replace links, and interview leads no longer land outside the data directory (Issues #1746, #1748).
- ✅ v3.4.111 (2026-11-18): SQLite connections now refuse symlinks before opening — the cache database, request-budget database, `stats` and automation lock databases no longer follow links or write outside the data directory, and automation queue appends fail closed on FIFOs and dangling links instead of hanging `agent run` after an action has executed (Issues #1739, #1741, #1743).
- ✅ v3.4.110 (2026-11-18): the local path-state fail-closed sweep now covers FIFOs and devices — automation queues, chat snapshots, the index cache, exclusive lock files and crawl hook directories no longer hang on special files, and `hr download-resume` validates `--output` before any platform request (Issues #1726, #1728, #1730, #1732, #1734, #1736).
- ✅ v3.4.109 (2026-11-18): local SQLite error classification and wider `-o` preflight coverage — `stats` no longer returns an all-zero report on cache locks or disk errors, `request-budget.sqlite3` read-only/disk-full failures are no longer misreported as corruption with delete-the-database advice, and `digest` validates `-o` before login and platform requests while `digest` / `stats` / `resume export` no longer atomically replace FIFO or device targets (Issues #1718, #1721, #1723).

- ✅ v3.4.108 (2026-11-18): non-privacy `clean`, `ai @file`, `resume import`, `stats` and `-o` preflight now fail closed on path state, so unreadable metadata and non-regular files are no longer skipped silently, reported as success, or read as blocking streams (Issues #1712, #1714, #1716).

- ✅ v3.4.107 (2026-11-18): model re-imports copy to a staging path and replace atomically, corrupt AI config is never overwritten by defaults, and unreadable session/key ciphertext is reported as a local IO error instead of a logged-out state (Issues #1705, #1706, #1709).

- ✅ v3.4.106 (2026-11-18): local state, config and registry reads are now fail-closed, so permission errors, non-regular files and empty salts are no longer treated as missing state and never overwrite existing history (Issues #1684, #1686, #1688, #1690, #1692, #1694, #1695, #1698, #1699, #1700).

- ✅ v3.4.105 (2026-11-18): stop-latch and state-file path metadata are now fail-closed, so permission errors, dangling links and non-regular files are no longer read as a missing latch or empty state (Issues #1680, #1682).

- ✅ v3.4.104 (2026-11-18): stop-latch reads and explicit recovery now fail closed on path type, so a directory or symlinked `stop.json` can no longer bypass the stop switch or crash mid-resume; CHANGELOG version ordering is covered by a structural test (Issues #1675–#1676, #1678).

## Long-term vision

**Make AI agents feel like real job-search copilots**, not just tool-call wrappers:

- agents should autonomously complete the full loop from search to screening to greeting to follow-up to interview prep
- users should only need to describe a target, such as "find remote Python roles above 30K", and let the agent execute the workflow
- all data should remain local-first, with privacy and compliance treated as primary constraints
